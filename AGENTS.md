# device-ui-testing-guidance — Repository Invariants

- **Zero runtime dependencies**: `bin/` and `lib/` MUST run with Node.js >= 20 standard library only. Never add mandatory npm dependencies to `package.json`. `playwright` / `playwright-core` is loaded dynamically only by the `audit` subcommand.
- **Guide contract (`skills/device-ui-testing-guidance/guides/<category>/<id>.md`)**:
  - Every guide MUST have YAML frontmatter with `id`, `category`, `title`, `description`, `keywords`, and `appliesTo`.
  - Every guide `id` MUST match its filename stem and be globally unique across all categories.
  - Every cross-referenced guide ID (backticked under `## Related guides`) MUST exist and is verified by `npm test`.
  - Keep guides concise, actionable, and token-efficient (invariants, root causes, Playwright assertions — no filler prose).
- **Static scanner discipline (`lib/static-scan.mjs`)**: Every rule MUST include a linked `guideId`, `keepWhen`, and `dropWhen` false-positive rubric, plus positive and negative test coverage in `test/static-scan.test.mjs`. Never use `\bwidth` (hyphen `-` triggers a word boundary and false-matches `max-width`) — always anchor property regexes with `(?<![-\w])` and skip leading whitespace after `}` before computing rule line numbers.
- **Headless non-focus-stealing auditor (`lib/audit.mjs`)**: Always run `headless: true` (never `--headed`), prefer system Chrome (`channel: "chrome"`) with fallback to `"msedge"` and bundled Chromium, and set `isMobile: true, hasTouch: true` on mobile/tablet viewports.
  - **Anti-shrink-to-fit overflow guard**: Under `isMobile: true`, Chromium inflates `window.innerWidth` when content overflows — always compare `scrollWidth` and `rect.right` against `Math.min(window.innerWidth, expectedWidth)` and track `rawVw - expectedWidth`.
  - **Overlay & screenshot order**: Check open `<dialog>`/`[popover]` for both out-of-bounds edges and unscrollable vertical clipping (`scrollHeight > clientHeight + 2` when `overflowY` is not `auto`/`scroll`). Capture base viewport screenshots **before** running interactive `--actions` so unclosed modals never pollute initial-state PNGs.
- **Test harness hygiene (`test/`)**: Never hardcode local user paths or private domains in tests or fixtures (resolve Playwright via `PLAYWRIGHT_PATH` env var). When spawning the CLI against an in-process `http.createServer`, always use async `execFile` (never `execFileSync`, which deadlocks the server's event loop).
- **Public release & sync**: Before publishing to GitHub/npm, grep for local paths/private domains, run `npm pkg fix` (`bin` without leading `./`, `repository.url` with `git+` prefix), verify `npm pack --dry-run`, and run `npm test`. After `npm publish`, confirm `npm view device-ui-testing-guidance version bin` is not `0.0.0-stage` (`stub: true`) and cold-cache smoke-test with a fresh `NPM_CONFIG_CACHE` via `npx -y device-ui-testing-guidance@latest`. Keep this repository as SSOT; run `npm run install:local` to mirror runtime files into `~/.gemini/config/plugins/device-ui-testing-guidance/` (then sync to Mac via local ops script outside this repo).
- **Verification command**: Run `npm test` after any code, guide, or manifest edit.
